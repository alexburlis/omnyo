# GitHub

Own standalone fork of upstream's MIT-licensed GitHub plugin (see [UPSTREAM.md](UPSTREAM.md)). It finds root checkouts, nested repositories and linked worktrees across Omnyo project sources on their owning machines. GitHub operations use the existing GitHub CLI authentication on the Omnyo server's primary machine; only results and safe authentication status return to the coordinator. No new account or credential is required. The coordinator retains cached rows, exclusions, links and sync state when that machine is unavailable.

The panel lists only work the signed-in GitHub account controls: issues it opened, pull requests it opened, and bot pull requests such as Dependabot on repositories where it has write access. Other people's issues and pull requests are never cached. Each sync reads the signed-in account again, so switching GitHub accounts takes effect on the next sync.

The panel is a GitLens-style Launchpad. Issues and pull requests share one list, ordered by the next action rather than by type: Ready to merge (security updates first), Blocked (conflicts, failing required checks, branch rules, behind the base branch), Requires follow-up (changes requested, optional checks failing), Needs your review, Waiting (review required, checks running), Checking with GitHub (GitHub has not computed mergeability yet), Drafts, Open issues and Recently closed. Color marks only what needs action: green can merge, red is blocked, amber needs follow-up. Each dense row shows the state glyph, title, number, repository lane color, check result, diff size, author and age; Review or Work on with agent, Merge, Open on GitHub and the row menu appear on hover, focus or selection. The list's collapsible group headers are the triage navigation (← and → collapse and expand them). The left rail holds two views, Launchpad (open work) and Recently closed, plus saved views and the repository scope: Save this view stores the current filter, type, view and repository scope under a name in this browser. The type segment switches between All, PRs and Issues. On Ready to merge, Merge all opens one confirmation that checks every pull request on GitHub, lets you untick any, then merges them one at a time at the checked commit with a per-row result and a Stop button. Selecting a row opens the Inspect sheet beside the list without losing your place: verdict, head and base branches, size, checks, merge, description, files changed and activity. Below about 60rem the sheet replaces the list and Back returns to it. Keys: j/k or arrows move, Enter opens, o opens on GitHub, / focuses the filter, Escape closes the sheet and ? lists every shortcut. The status bar at the bottom of the list states what the cache covers, when it last synced and when the next background sync is due, with Sync now. The filter accepts text, #number and repo:, author:, label:, assignee: and no: qualifiers; label: qualifiers must all match, as on GitHub. The browser remembers the view, type, filter, repository scope and collapsed groups. Manage repositories in the rail opens the inclusion settings. When sync coverage is incomplete, the list says so instead of claiming nothing is open and offers Refresh now.

The GitHub navigation icon shows the combined cached open PR and issue count, including zero. Hover the count for separate totals. a dashed badge marks counts that may be out of date; `—` means counts are unavailable or have not synced. Counts refresh with sync, repository inclusion changes and reconnection, across all included repositories regardless of panel filters.

## Use

- `omnyo workspace-github repos --json` lists discovered repositories.
- `omnyo workspace-github sync --json` refreshes from GitHub.
- `omnyo workspace-github issues [owner/repo] --json` and `prs` list cached open items.
- `omnyo plugin rpc call workspace-github status --json` reports authentication, repositories, sync time, warnings and offline-machine notices. The `listItems` RPC and `prs --json` include `pullReview` and `pullMerge` when GitHub supplies those states for an open pull request. The panel calls `listItems` with `includeBody: false` to skip descriptions. The RPC includes descriptions by default.
- Configure explicit additional repositories through `omnyo plugin config workspace-github set extraRepos owner/repo`.
- In Settings → Plugins → GitHub, **Excluded repositories** lists the current project and extra repositories. Search by repo or project, filter All / Included / Excluded, and click a repository switch to include or exclude it immediately. Excluded repos remain available to turn back on. Refresh updates the list from current project sources without syncing GitHub. Exclusions override discovery and Extra repositories, match without case sensitivity, and recognize known renamed origins. Including a repo restores cached rows immediately. Saved exclusions from the old text setting migrate automatically.
- `printf '%s' '{}' | omnyo plugin rpc call workspace-github repositorySettings --input-file /dev/stdin --json` lists repository inclusion settings. Toggle through `printf '%s' '{"repo":"owner/repo","excluded":true}' | omnyo plugin rpc call workspace-github setRepoExcluded --input-file /dev/stdin --json` (`false` includes it).

Repository discovery scans at most three folder levels below each project source; it stops at Git checkouts and skips directory symlinks, dependencies and build outputs. A folder whose `.git` file points to a removed worktree is skipped, and a folder that cannot be read is reported without stopping the rest of the scan. When a machine is offline, the panel keeps the repositories it last found there and shows a notice with that date; an offline machine never scanned before shows a warning. Linked worktrees are deduplicated by origin; account-rename aliases use the canonical repository name returned by GitHub. Discovery refreshes on the settings Refresh button, Extra repositories changes, and every GitHub sync. Background sync runs every 15 minutes and fetches up to 100 open and 50 closed issues opened by the signed-in account, and the 50 newest open and 30 newest closed/merged PRs per repo before the pull request filter. Counts describe that bounded recent cache, not all-time GitHub totals. The same GraphQL request also caches head and base branches, additions, deletions and changed files, the latest commit's check rollup, reviewers and review requests, comment counts, label colors, issues a pull request closes, and created, closed and merged times. Rows cached under a repository name that GitHub now reports as renamed move to the new name, or are dropped when the new name is already tracked. About four seconds after a sync, pull requests whose mergeability GitHub had not computed yet are checked again.

Pull-request details use a bounded in-memory cache. Reopening within 30 seconds
reuses the fresh model; older details remain visible while revalidating. Changes
and explicit refreshes invalidate the model immediately. Failed revalidation
shows an error beside the last known details. Header and panel status reads share
in-flight work, and repository syncs overlap at most two reads under the existing
VCS scheduler.

## Develop

`pnpm install --frozen-lockfile`, then `pnpm verify`. Commit the change, then install it on the coordinator with `pnpm package:runtime && pnpm install:runtime -- --machine <host-id>`. Do not install this checkout directly: the plugin would then run live from the working tree. Disable the official `github` plugin only after verifying this plugin. See UPSTREAM.md and LICENSE for fork provenance.

## Close and merge

Issue details and pull request details show Close or Reopen when the signed-in GitHub account has permission. Close, Reopen and Merge all confirm in the same kind of dialog, which checks GitHub permission first and stays on the current view. The merge dialog repeats the pull request's merge status, checks, review state, size and branches, and offers the repository's enabled merge methods. Read-only repositories explain why these actions are unavailable. GitHub reviews, checks, conflicts, and branch rules still apply; Omnyo does not request an administrator override, enable auto-merge, enqueue a merge, or delete a branch.

The same actions are available through the plugin RPC SDK and `omnyo plugin rpc call workspace-github METHOD --input-file FILE --json`:

| Method          | JSON input                                                                                |
| --------------- | ----------------------------------------------------------------------------------------- |
| `itemActions`   | `{"kind":"pr","repo":"owner/repo","number":7}` (`kind` can also be `issue`)               |
| `setIssueState` | `{"repo":"owner/repo","number":7,"state":"closed"}`                                       |
| `setPullState`  | `{"repo":"owner/repo","number":7,"state":"closed"}`                                       |
| `mergePull`     | `{"repo":"owner/repo","number":7,"method":"squash","headOid":"FULL_REVIEWED_COMMIT_SHA"}` |

Use `state: "open"` to reopen. Read `itemActions` before merging; use its `headOid` and an enabled `mergeMethods` value (`squash`, `merge`, or `rebase`). The server checks permissions and merge requirements again, and GitHub atomically rejects a changed head commit. A false or failed merge response never marks the cache as merged. These write methods require the user's action; providing a JSON file does not authorize an agent to close or merge an item.
