# Inline UI

Omnyo plugin for native visual blocks, assistant typography, HTML visualizations and Markdown previews.

- Source: app.tsx registers public SDK slots; blocks.tsx, chart.tsx, comparison.tsx, steps.tsx and records.tsx render native React. record-fields.ts owns status-table/file-card validation and the parsing of those two fence languages; a status table takes two columns, or three when the third holds the details; fences.tsx renders them through experimental_codeFenceRenderer, showing Omnyo's original code while streaming or when a fence cannot be read at all. block-fields.ts owns the one tone vocabulary every block shares (neutral, info, positive, warning, negative, muted; aliases success, error and note) and the callout, badge, metric-row and progress validators. tests/*.test.ts run with node --test. file-card local paths use the SDK's semantic FileLink with the containing message's machine/workspace, after sdk.hosts.pathsExist confirms the path on that machine; a missing path shows File not found and never mounts PlanAction; web URLs use host Markdown. Never use a plugin-owned anchor for files. Native blocks use no iframe or plugin-owned file loader. The inherited visualization renderer in visualizations.tsx uses its own sandboxed frame and preview-server.ts reads only source-relative files through the public SDK. Keep its path, size, encoding, HTTP(S) link and source-window checks. The plugin has no persistent data store. PlanAction uses the public SDK to call Pursue, which owns linked-plan reads, model defaults and execution. PlanAction keeps one in-memory preview per chat and link, shows it while revalidating, and refreshes on mount or focus only after five seconds. server.ts relays lifecycle events of Pursue-created threads as `plan-run-changed`, because a plugin app only receives its own plugin's realtime channels; a card refreshes only for its own run or a new run from its chat.
- Use pnpm. Run pnpm test, pnpm lint, pnpm typecheck, pnpm format:check, pnpm test:e2e -- --output <output-path>, and omnyo plugin build.
- Keep CSS under the owned root data-omnyo-inline-ui attribute and native block classes. The assistant Markdown selector is verified against Omnyo 0.46.0 and requires review when Omnyo changes its DOM.
- A block never shows a parse error. Tolerate authoring slips where the intent is unambiguous: ignore unknown fields, read unknown tones as neutral, drop a mismatched `tones` or unusable `columns`, pad missing details, accept bare placeholders such as `<chat-id>`. Input that still cannot render as its block goes to invalid.tsx's `ReadableFallback`, which shows every supplied cell as quiet plain text, with the reason only in `data-reason`. Never guess or drop a cell to force the styled block. Treat as markup only real HTML formatting (comments, closing tags, attributes with `=`, self-closing tags, `br`/`hr`/`img`/`wbr`); all block text renders as inert React text, never HTML.
- Agents sometimes write a status table's cells row by row inside `labels` (label|value or label|value|detail), as in a Markdown table. record-fields.ts `readStatusTable` rebuilds those rows only when every repeated value, and every repeated detail that `details` also supplies, matches exactly, so no cell is guessed or dropped; any other count mismatch renders the readable fallback. Do not teach agents this form: the skill and server.ts describe columns.
- server.ts instructions stay in every agent's context after compaction, while the skill may not, and many chats never load the skill: keep the one-line directive form with the attribute names of every block, the tone vocabulary and its aliases there and in the skill in agreement. Add every new block or attribute to server.ts as well as the skill.
- comparison-bars shares one zero-inclusive scale across both supplied series; ordered-steps shows states only when provided. Preserve full labels, exact supplied values and measurement notes. Disable/reload must remove the typography attribute.
- tests/ contains browser E2E verification, not production test seams.

- Inline UI 0.4.0 combines the native blocks with the former inline-vis plugin. Preserve the old inline-vis directive/fence IDs and both bundled skills for saved messages. Keep LICENSE and NOTICE with the inherited renderer. preview-ui.tsx owns the small presentation helpers formerly imported through core-private aliases; do not import from core source.
