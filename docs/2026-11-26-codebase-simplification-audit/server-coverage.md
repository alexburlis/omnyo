## Additional investigation and retain/reject decisions

The sweep continued beyond the earlier leads. No additional material opportunity met the evidence/benefit threshold in this lane. These decisions prevent repeated speculative plans:

- **Retain archive/identity and database migration compatibility.** Historical names/large files are connected to current startup holds, journals, runtime identities, legacy archive ingestion and migration hashes. No last-consumer/support evidence permits deletion. Full fault-matrix verification is a future prerequisite for changing these owners, the audit records this implementation prerequisite.
- **Retain independent filesystem writers.** `secret-storage/files.ts`, `server-archive/json-file.ts` and `file-transfer/replace-file.ts` have similar temp/rename syntax but distinct private mode, durability, Windows ACL/state replacement, directory fsync, create-only and optimistic-conflict contracts. A shared helper with switches would retain the existing complexity in another owner. No RF gain counted.
- **Reject a separate checkout-lock micro-card.** `host-workspace/checkout-mutation-lock.ts` and provider `locks.ts` duplicate a short checkout-admission wrapper/key prefix, but both already use `process-local-lock`. The provider's nullable non-repository resolution and host's throwing contract differ. Preserve two wrappers. The small potential deletion does not justify a broader lock API or co-mingling it with RF-204. Shared inode/file/ref locks remain untouched.
- **Retain watcher recovery boundaries.** Root/path subscription retries, metadata promotion and child proxy recovery are not competing truth stores for the same event. Collapsing them would lose disposal/abort/replay responsibilities without established redundancy.
- **Retain process execution/admission boundaries.** Public SDK versus private host runners, VCS local/network scheduling and leader-first cleanup enforce resource and platform rules. Similar spawn code is not proof of one removable implementation.
- **Retain separate domain/inbox projection.** Shared words such as waiting/working do not prove identical eligibility, archive or display policy. RF-203 shares raw facts only.
- **Retain Connect adapters and presence modes.** Shared hashed credential resolution already removes duplicate lookup. Account suspension remains a separate caller policy. Marked tunnel status and timestamp presence are explicitly tested supported modes, supported behavior that remains intact.
