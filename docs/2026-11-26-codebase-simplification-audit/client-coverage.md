# Client, desktop and mobile audit coverage

The largest supported reductions in this slice are a shared secondary-panel display mapping and one owner for composer selection sequencing. Realtime target counting is smaller but removes a rule copied into three supported clients. The cards preserve platform lifecycles and all existing UI behavior.

## Snapshot, method and limits

Inspection used the read-only snapshot `$AUDIT_WORKTREE` at **`e9e1b74c3b906edbf2d4b4c3da8f930c62e24f9e`**, verified with `git rev-parse HEAD` on 26 November 2026. `git symbolic-ref --quiet --short HEAD` confirmed detached HEAD. `GIT_OPTIONAL_LOCKS=0 git -c core.fsmonitor=false status --porcelain --untracked-files=no` returned no tracked changes. The previous audit was read from the canonical checkout at `docs/2026-11-25-material-simplification-audit.md`, because that uncommitted report is absent from the source snapshot. Its findings were rechecked against the snapshot rather than assumed current. The retained writes in this slice are this ledger, `client-issues.md` and RF-100 through RF-104 cards in the canonical audit directory.

Methods included source inventory, package/export/script inspection, direct implementation reading, caller/import tracing, focused test reading and an in-memory text comparison of two duplicate blocks. No dependency installation, source edit, test/build execution, native/UI session, benchmark, network request, publication or service mutation occurred. Source searches began with `rg --files` and `rg`. The absence of a textual caller was used as a lead only. It was not treated as proof that a compatibility path could be deleted.

Depth terms in the ledger are deliberate. **Reviewed** means a representative real implementation path, its consumers and relevant verification anchors were inspected for simplification mechanisms. It does not mean every line of every component was read. **Sampled** identifies broad source families where only selected mechanisms were followed. This slice does not claim exhaustive per-component review of the 1,276 browser source files or runtime equivalence. UI states, native integration and performance require the focused evidence described in each card before implementation acceptance.

## Additional browser implementation checks

- **Onboarding, layout and settings.** `apps/app/src/App.tsx` mounts `OnboardingGate` and `ServerMoveOverlay`. `OnboardingGate` keeps the local seen/closed state separate from the persisted `onboardingCompletedAt` setting during startup and error handling. `OnboardingGate.test.tsx` anchors those branches. `settings-view-split.tsx` feeds route selection through `resolveSettingsRoute`, which gives installed plugin details and project/machine settings distinct paths. `App.project-settings-routes.test.tsx` anchors route behavior. These reads support retaining the distinct UI states and their existing shared settings owner.
- **Machine and project dialogs.** `ServerMoveOverlay` derives state from latest/followed move and destination health, selects polling policy based on realtime connection, then uses one-shot refs for navigation and cache invalidation. `ServerMoveOverlay.test.tsx` exercises those transitions. `AppLayout` mounts `ProjectActionsProvider`, which owns rename/delete/attach picker state and closes dialogs after successful mutations. `ProjectActionsMenu.test.tsx` and `ProjectPathDialog.test.tsx` are representative consumer checks. Retain these transaction-specific owners.
- **Tools, PR and review scenes.** `SkillDetailView` selects file presentation and feeds independent chunks into the Markdown viewer. An isolated reproduction found the fence-matching defect in [ISS-002](incidental-findings.md#iss-002--skill-preview-chunking-can-split-a-code-fence). `PullRequestStatusPill` delegates status description and check state to existing helpers while owning UI visibility and width. `PolishReview.stories.tsx` consumes its typed manifest as a live story fixture. The manifest has a verification consumer even though it is outside ordinary app runtime.
- **Composer editor.** `promptEditorExtensions` composes the concrete Tiptap document, history, mention and decoration extensions. The placeholder/decorations callbacks keep caller-provided draft observers separate from editor schema. `prompt-decoration-extension.test.ts` is an existing fixture anchor. The editor extension family retains distinct behavior for document history, mentions and decoration.

The additional checks document representative paths across these groups. Detailed component-by-component and native interaction coverage remains outside this audit's proof.
