# RF-073 — Decide one owner for the prompt-search and inline-visualization code that public Prompt Library and inline-vis share with private Skills and Inline UI

**Rank and disposition**

**Rank:** _unranked: the index step did not run (see [the folder README](../README.md))_

- **Verdict:** adjusted, and decision-needed. The central claim holds: on 24 November 2026 the public built-in plugins `plugins/prompt-library` and `plugins/inline-vis` were copied into the private plugins `skill-discovery` (Skills 0.6.0) and `inline-ui` (Inline UI 0.4.0), and core now hides the public plugin when the private one is running. The sweep understated the overlap and overstated the divergence. After normalising formatting, the copies are 95 to 99 percent identical statement for statement. Most of the "59 differing lines" in `ranking.ts` are line wrapping, because the public repository formats at 80 columns and the private one at 100. Neither copy has had a fix since the fork, so the porting cost is still ahead, not yet paid. The sweep's option C ("private successors import the public plugins through the plugin SDK") is not possible as written, because the plugin SDK does not carry plugin code. This card replaces it with two workable variants.
- **Potential:** medium. About 3,900 public and 3,900 private handwritten production lines describe the same two features. Depending on the option chosen, one copy of the inline renderer (about 1,580 private lines) and the core consolidation machinery that names private plugins (about 240 public lines) can disappear.
- **Confidence:** high on the facts (Proven by inspection). Medium on the line projections. Low on which option is right, because that depends on product intent that only Alex holds.
- **Readiness:** decision-needed. Every option except "retain and document" changes which plugin owns a supported feature in the owner's private installation, or what the public repository offers.
- **Effort:** option A takes under an hour. Option C1 (inline-vis only) takes about 1 to 2 days across both repositories. Option C2 (Prompt Library) takes 3 to 5 days, including a data migration. Option B (publish the successors) is unknown, because it depends on how much of Skills and Inline UI can be published.
- **Risk:** option A carries none. The other options affect saved chat messages that contain `inline-vis` fences and directives, starred and saved prompts stored by Skills, the **Ctrl+R** "Search prompts" binding, and which plugin's bundled `inline-vis` skill agents see. Retiring the public plugins outright would remove a capability that public users have and is not offered here.
- **Prerequisites:** the owner's decision between the options in "Proposed end state". For Prompt Library, RF-129 should land first or be folded into C2.
- **Related or overlapping:** RF-129 (drop Prompt Library's per-call push of starred prompts into Skills) edits the same forwarding block, `plugins/prompt-library/server.ts:49-152`. Option C2 deletes that block, so RF-129's savings are contained in C2 and must not be counted twice. RF-006 and RF-043 are other one-time adoption paths and are unrelated. The needs-you to ask-user-question entry in the same consolidation map is unaffected, because both of those plugins live in this repository.
- **Why it deserves its place:** this is the largest piece of duplicated product knowledge across the two repositories, and it is the only place where public core hard-codes private plugin ids and the private repository URL. It is not dead code, so it ranks below verified deletions. Its value is preventing silent drift between two copies of a ranking algorithm and a sandboxed-iframe security boundary.

*Recommended default (judgment, not evidence).* Choose **C1 for inline-vis**, because the renderer is a self-contained security boundary (a sandboxed opaque-origin iframe with path, size and encoding checks) that has no stored data, and a single owner removes the bigger copy without changing what users see. Choose **A for Prompt Library** until Alex decides whether Skills' extra prompt features belong in the public product, and land RF-129 meanwhile. Option B is the better long-term answer for both pairs if Alex intends to publish Skills or Inline UI.

*Preservation argument for C1.* Public inline-vis already renders every `inline-vis` fence and `::inline-vis{…}` directive. It is the renderer whenever Inline UI is absent, and its frame, theme and preview modules are behaviourally the same as Inline UI's (the comparison above). Inline UI's agent instructions (`omnyo-plugins:inline-ui/server.ts:10`) refer to "the inline-vis skill" by name, and public inline-vis bundles a skill with that name. After C1, Inline UI and inline-vis both run, and `consolidatedInto("inline-vis")` returns `undefined`, so inline-vis appears in Settings again and contributes its bootstrap assets. Non-goals: no change to the fence grammar, the directive attributes, the iframe sandbox, the 80 to 2,000 pixel height clamp, the 5 MiB file limit, or the Markdown card.

*Remaining uncertainty for C1 (Hypothesis).* the owner's own installation may have `inline-vis` disabled, because it was hidden while consolidated. It may also hold user-level Inline UI settings that the renderer read. The investigation gate checks both.

**Rollback and stop conditions**

- *Rollback:* each checkpoint is one commit in one repository. Reverting the Inline UI 0.5.0 commit restores the bundled renderer. Reverting the core commit restores the consolidation entry. No persisted data changes under A or C1, so rollback has no data implications. C2 does change data and needs its own rollback plan.
- *Stop* if step 2 finds a behavioural fix present in one copy only. Port it first, then re-run the comparison.
- *Stop* if step 3 shows Inline UI renderer settings with no inline-vis equivalent. Those settings must move to inline-vis first, or the item reverts to option A.
- *Stop* if Alex wants inline visualizations to be configurable or disableable independently of the public built-in inline-vis. In that case C1 changes product behaviour, and option A or B applies.
- *Stop* if a check shows two `inline-vis` skills, or a missing one, in an agent's skill list. That means skill de-duplication depends on the consolidation hiding, which this audit did not verify.
- *Smaller alternative:* option A, which costs one note per private plugin and keeps everything as it is.
